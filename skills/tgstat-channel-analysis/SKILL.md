# Анализ каналов TGStat

Получай реальные данные TGStat и возвращай компактную сравнительную таблицу с источниками и датой снимка. Не подменяй замер предположениями о закупках, ботах или органическом трафике.

Для расширения анализа на ER/ERR, посты, реакции, цитирование, stories или поиск читай [карту методов](references/analytics-map.md). Она отделяет документированные возможности от реализованных сборщиков и объясняет ограничения тарифов и пагинации.

## Доступ и сбор

Предпочитай Chrome DevTools MCP: доступный прямой инструмент или child MCP через GPTAdmin. Сначала проверь список вкладок и наличие нужного профиля с TGStat. Статус `online` в GPTAdmin не доказывает доступ к авторизованному Chrome. Служебный Chrome с пустой вкладкой не равен личному Chrome, даже если оба доступны через CDP.

Если пользователь попросил свой Chrome, используй поддерживаемый `--autoConnect` официального Chrome DevTools MCP. [Подключение](references/devtools.md) содержит способ без SDK-зависимостей. Не меняй общий gateway ради одного анализа. Не переходи на мышку, если пользователь требует DevTools. Соблюдай ограничения размещения браузеров в среде пользователя.

Открой один канал, проверь название/username, затем сними запрос панели и повторяй его для остальных каналов через `evaluate_script` и same-origin `fetch`. Не копируй cookies, CSRF или токены в ответы, файлы и навык. Читай CSRF из `meta[name=csrf-token]` внутри страницы непосредственно перед запросом. Не покупай доступ и не меняй канал.

Проверенные API и разбор реализованы в [scripts/collect.js](scripts/collect.js). Этот файл задаёт `tgstatCollect(options)` в странице; после загрузки вызови функцию через DevTools. Метаданные и ошибки сохраняются с числовыми рядами. Новые изменения API проверяй на одном канале по реальной панели.

Бюджет сбора: один MCP child с heap 256 MiB, одна сериализованная очередь, один запрос одновременно, таймаут запроса 15 секунд, сбор до 120 секунд, до 40 страниц подписчиков на канал. Нет новых browser workers, демонов или широких тестов. На больших заданиях дели каналы на партии; не умножай бюджет. Закрывай только свой MCP child, сохраняя Chrome и чужие вкладки.

## Период и показатели

По умолчанию полгода — шесть последовательных месячных интервалов до начала сегодняшнего дня в часовом поясе пользователя. Явно показывай границы (например, 13.04–12.10), а не называй их календарными апрелем–сентябрём. Пользовательские календарные месяцы имеют приоритет. Не включай неполный день в месячные сравнения.

Подписчики:

- Текущий размер: последнее значение аудитории и его время.
- Наблюдаемая убыль месяца: сумма модулей отрицательных почасовых изменений; средняя убыль — среднее этих месячных сумм; максимум — наибольшая сумма за месяц с его границами.
- Процент месяца: наблюдаемая убыль / аудитория на начало периода × 100. Начальный размер можно восстановить как `size - delta` у первой строки, только если граничное покрытие подтверждено.
- Отдельно сохраняй чистое изменение размера. Сумма почасовых минусов не равна чистому сокращению аудитории. Это не число уникальных отписавшихся, не когортное удержание и не доказательство накрутки. Приток в том же часу скрывает часть уходов, а повторные подписки могут учитываться неоднократно.
- Убирай дубли по каналу и timestamp. Проверяй непрерывность размера: предыдущий `size` должен равняться следующему `size - delta`. Расхождения и отсутствующие часы сохраняй; не исправляй источниковые данные догадкой.

Просмотры:

- «Обычно на пост»: текущий показатель TGStat «Средний охват 1 публикации» / последняя точка `posts-views-avg-chart`. Это среднее TGStat, а не медиана отдельных постов и не гарантированный охват за 24 часа.
- Если нужны первые 24 часа, отдельно собирай рекламный охват `posts-views-adv-chart` с `period=24h`; даты обновления могут отличаться.
- Суммарно за месяц: сумма дневных точек `posts-views-chart` внутри границ. Это просмотры, полученные всеми публикациями за эти дни, включая старые посты; не сумма lifetime-охватов постов, опубликованных за месяц, и не уникальные зрители.
- Не вычисляй месячный факт как средний охват × число постов. Это допустимо лишь как явно обозначенный прогноз, когда фактической серии нет.
- `null` не равен нулю. Проверяй пропущенный день через `posts-views-details?ts=<unix_seconds>`. Сохраняй факт отсутствия точки, текст детализации и полноту покрытия. Даже если детализация показывает 0, называй итог показателем по данным TGStat, а не доказанным реальным нулём просмотров.

## Обработка и выдача

[scripts/analyze.py](scripts/analyze.py) обрабатывает выгрузку просмотров или подписчиков и печатает JSON-сводку, включая покрытие и несогласованность. Запуск: `python3 scripts/analyze.py INPUT.json --start YYYY-MM-DD --end YYYY-MM-DD`; конец исключается. Даты и каналы всегда задаются пользователем или выводятся из текущего запроса, фиксированного списка каналов нет.

Покажи текущий размер, среднюю и максимальную месячную убыль, месячные проценты; для просмотров — текущий средний охват поста, среднюю месячную сумму за период и последний полный месячный интервал. Подробности по месяцам можно вынести в файл. Сохрани очищенные исходные данные без авторизации, ссылки на страницы каналов и время снимка. Отдельно сообщи реальные ограничения источника. Проверь хотя бы одну точку по видимой панели и полноту всех интервалов перед завершением.
